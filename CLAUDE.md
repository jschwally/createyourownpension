# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Static HTML website for "Create Your Own Pension" — plain HTML/CSS/JS, no build step, no frameworks, no package manager. Every page is a standalone `.html` file that links directly to shared assets in `css/` and `js/`.

## Development

There is no build, lint, or test tooling in this repo. To preview changes, open the HTML files directly in a browser, or serve the directory locally, e.g.:

```
python -m http.server 8000
```

Then visit `http://localhost:8000/index.html`.

## Conventions

- Every page repeats the same `<header class="site-header">`/`nav`/`<footer>` markup verbatim (there is no templating/includes mechanism). When changing the nav (adding/removing/renaming a page), update the `<nav>` block in **every HTML file at the repo root** (33 as of this update, not a fixed count — re-check with `Glob *.html`) identically. Current nav order: Home, How It Works, Calculate My Gap, Resources, FAQ, Schedule A Call. The last nav item uses the `.nav-cta` class to render as a gold CTA button — keep it last.
- Nav labels intentionally differ from page titles/filenames: `calculator.html` is labeled "Calculate My Gap" and `faq.html` is labeled "FAQ" in the nav (both have been renamed since earlier versions of this doc — don't trust nav-label claims elsewhere in this file without spot-checking).
- The header logo is an `<img>` (`images/CYOP_logo_w_Texas.png`, alt "Create Your Own Pension") inside the `.site-title` link. Image filenames under `images/` use underscores, not spaces (e.g. `hero_image.png`, `3bar_income_gap.png`, `john-schwalenberg-headshot.png`) — keep new assets consistent with that convention.

## Brand design system (css/style.css)

- Brand tokens are CSS custom properties on `:root`: `--navy`, `--gold`, `--white`, `--gray-blue`, `--charcoal`, `--slate`, plus `--font-heading` (Playfair Display) and `--font-body` (Inter), loaded via Google Fonts `@import` at the top of the stylesheet. `h1`/`h2`/`h3` use `--font-heading` automatically; everything else uses `--font-body` — don't hardcode font-family elsewhere.
- Each page's main content is wrapped in `<main><section class="section section--white|section--gray-blue|section--navy"><div class="section-inner">...</div></section></main>`. `.section--navy` (used for Section 9 of `index.html`) sets white headings and gray-blue body/subheadline text so content stays legible on the dark background — text color is not automatic, so any new content added inside a `.section--navy` block must rely on these overrides (or be given its own color) rather than the default charcoal/navy text colors. `.section--navy a { color: var(--gold); }` applies to every link, including `.btn` CTAs — `.btn-primary` and `.btn-secondary-inverse` both need an explicit `.section--navy .btn-*` color override (already present) or their button text silently turns gold-on-gold/gold-on-transparent instead of the intended white; any new button variant used inside a navy section needs the same override. The same specificity gotcha applies to any text component with its own color, not just buttons: `.section--navy p { color: var(--gray-blue); }` (specificity 0,1,1) silently overrides a plain single-class rule like `.trust-line { color: var(--white); }` (0,1,0) unless a matching `.section--navy .trust-line` override exists (already present, used in the closing navy section of `schedule.html`) — check specificity before assuming a new text-color class will "just work" inside `.section--navy`. `.section-inner` caps content width; don't put text directly inside `.section` without it. Sections alternate background: on single-section pages (resources, faq, schedule) that alternation is across pages in nav order; on pages with multiple stacked sections (`index.html`; formerly also `about.html`, now superseded by `about-john.html`, see below), alternate white/gray-blue section-by-section down the page instead — the hero counts as the first (non-`.section`) block, so the next section starts white. `.section-subheadline` (slate, 1.125rem) is the standard style for a supporting line under an `<h2>`/`<h3>` section headline. `.subsection-grid` lays out a row of `.subsection` blocks (bold `<h3>` + body copy) three-across, collapsing to one column at 860px — used in Sections 2 and 3 of `index.html`. The `.subsection-grid--four` modifier (add alongside `.subsection-grid`) switches it to four-across for Section 8's subsections; it still collapses straight to one column at 860px like the base grid (no 2x2 tablet tier, unlike `.stat-grid`). `.section-image` is a full-width image block that can follow any section's content — currently unused (Section 2's chart moved into `.section-split`, see below) but kept as a general-purpose option. `.section-split` lays out a two-column text+image row (used with `.section-split-content` / `.section-split-media`) inside a `.section`, collapsing to one centered column at 860px — used at the top of Section 2 (headline/subheadline/body left, income gap chart right — the chart carries a `.chart-image` class capping it at `max-width: 480px` and centering it via `margin: 0 auto`), and in Section 4 for the founder headshot (`images/headshot.png`). Below the split, Section 2's three items are `.strip-list` — full-bleed `.strip` bands (gray-blue background, left-aligned bold `<h3>` + body copy in a `.strip-inner` max-width wrapper), stacked vertically, not the `.subsection-grid` three-across pattern. `.strip-list` sits as a sibling of `.section-inner` (not nested inside it) and uses the same negative-margin full-bleed technique as `.footer-legal-bar` (`margin: 0 -1.5rem` cancels `.section`'s own horizontal padding) so each strip's background spans the full section width edge-to-edge while `.strip-inner` still caps the text at `--max-width` for readability. `.trust-indicators` is a gold-dot checklist (forced left-aligned even inside a centered `.section-split-content` on mobile) — used for the three credibility lines under Section 4's body copy. `.step-grid` lays out `.step-card` items three-across, collapsing to one column at 860px — used in Section 5 for the "Three Steps" process. Each `.step-card` is `position: relative` so its `.step-icon` (60px, `position: absolute; top/right: 2rem` — matched to the card's own padding so it sits flush with the padded content area, not the card's outer edge) can pin to the top-right corner independent of content flow. `.step-number` is a large standalone Playfair Display numeral (3rem, gold, no circle/background) sitting at the top-left of the normal content flow — it and the icon are positioned independently (one in-flow, one absolute), not part of a shared flex row. The three step icons are 60px by default; Card 3's retirement icon uses an added `.step-icon--large` modifier (80px) — the icons are not uniformly sized despite sharing the base `.step-icon` class. `.section-cta` centers a single `.btn` below a section's main content, used for the "Calculate Your Gap Now" and "Schedule a Call" CTAs closing Sections 5 and 6. `.stat-grid` lays out `.stat-card` items (large gold Playfair Display `.stat-number` + `.stat-label`) — the only three-tier responsive component on the site: 4-across desktop, 2x2 at 860px, single column at 560px — used in Section 6. `.cta-support` (bold, slate) and `.cta-disclosure` (small, slate, width-capped) are optional lines that can follow a `.btn` inside `.section-cta` — used in Section 7 under the calculator CTA;
